# 한국석유관리원 일일언론동향 자동화

**Supabase 사용:** 기존 프로젝트에 뉴스 전용 테이블을 추가했습니다.
수집·검토·발송의 DB 연결 설정은 [Supabase 연결 안내](supabase/README.md)를 보세요.
Supabase 환경변수가 없으면 아래의 기존 GitHub 파일 방식으로 동작합니다.

매일 아침 뉴스를 모아 섹터별로 정리하고, 담당자가 뺄 기사를 눌러 걸러낸 뒤
텔레그램과 이메일로 최종본을 보냅니다. 받은 내용을 그대로 복사해
카카오톡으로 전 직원에게 공지하는 것을 전제로 만들었습니다.

```
06:40  뉴스 수집 → 섹터 분류 → 중복 묶기 → 초안 저장
  │
  │    담당자: 검토 페이지에서 뺄 기사 클릭 (누르면 바로 저장)
  ↓
08:00  최종본 발송 → 텔레그램 · 이메일 → archive/ 에 보관
```

- **섹터**: 석유관리원 / 공공기관 / 정부·정책 / 에너지
- **맨 위 한 줄**: 브렌트·WTI·원달러 시세
- **⚠️ 표시**: 담합·국정감사·가짜석유 등 기관이 대응할 수 있는 키워드가 걸린 기사
- **(외 N건)**: 같은 사안을 여러 매체가 쓴 경우 대표 1건만 남기고 묶은 표시
- **금요일 08:30**: 그 주 요약을 따로 한 번 더 발송

## 처음 한 번만 하는 설정

준비물 5가지입니다. 순서대로 하시면 됩니다.

### 1. 텔레그램 봇 만들기

1. 텔레그램에서 **@BotFather** 를 검색해 대화를 시작합니다.
2. `/newbot` 을 보내고, 봇 이름과 아이디(`_bot` 으로 끝나야 함)를 정합니다.
3. 받은 토큰(`8123456789:AAH...` 형태)이 **`TELEGRAM_BOT_TOKEN`** 입니다.
4. 만들어진 봇과의 대화창에서 아무 메시지나 한 번 보냅니다. *(이걸 해야 다음 단계가 나옵니다)*
5. 브라우저에서 아래 주소를 엽니다. `<토큰>` 자리에 3번 토큰을 넣으세요.
   ```
   https://api.telegram.org/bot<토큰>/getUpdates
   ```
6. 결과에서 `"chat":{"id":123456789` 의 숫자가 **`TELEGRAM_CHAT_ID`** 입니다.

### 2. 네이버 검색 API 키 받기 *(권장, 건너뛰어도 동작)*

기존 동향과 같은 `n.news.naver.com` 링크로 수집하려면 필요합니다.
키가 없으면 구글뉴스 RSS로 자동 대체되지만, 국내 기사 품질이 떨어집니다.

1. [developers.naver.com](https://developers.naver.com/apps/#/register) 에서 애플리케이션을 등록합니다.
2. 사용 API에서 **검색** 을 선택합니다.
3. 발급된 Client ID / Client Secret 이 **`NAVER_CLIENT_ID`** / **`NAVER_CLIENT_SECRET`** 입니다.

무료이고 하루 25,000건까지 쓸 수 있습니다. 이 시스템은 하루 25건 정도 씁니다.

### 3. Gmail 앱 비밀번호 발급

1. 발송에 쓸 구글 계정에서 **2단계 인증을 먼저 켭니다.** (안 켜면 다음 메뉴가 안 보입니다)
2. [앱 비밀번호](https://myaccount.google.com/apppasswords) 에서 새 앱 비밀번호를 만듭니다.
3. 나온 16자리가 **`GMAIL_APP_PASSWORD`** 입니다. 계정 주소는 **`GMAIL_USER`**.
4. 받는 사람은 **`EMAIL_TO`** 에 넣습니다. 여러 명이면 쉼표로 구분합니다.

### 4. GitHub 토큰 만들기 *(검토 페이지가 저장할 때 씁니다)*

1. [Fine-grained token 발급](https://github.com/settings/personal-access-tokens/new) 으로 갑니다.
2. **Repository access** → *Only select repositories* → 이 저장소만 선택.
3. **Permissions** → *Repository permissions* → **Contents: Read and write**.
4. 만료일을 정하고 발급합니다. 이 값이 **`GH_TOKEN`** 입니다.

> 만료일이 지나면 검토 페이지의 저장이 멈춥니다. 달력에 적어두시고,
> 만료되면 새로 발급해 Vercel 환경변수만 바꾸면 됩니다.

### 5. Vercel에 검토 페이지 올리기

1. [vercel.com](https://vercel.com) 에 **GitHub 계정으로** 로그인합니다.
2. **Add New → Project** 에서 이 저장소를 가져옵니다(Import).
3. 빌드 설정은 손대지 않고 그대로 둡니다. (별도 빌드가 없는 구조입니다)
4. **Environment Variables** 에 아래 5개를 넣습니다.

   | 이름 | 값 |
   |---|---|
   | `REVIEW_PIN` | 담당자가 쓸 PIN 숫자 |
   | `SESSION_SECRET` | 아무도 모르는 긴 임의 문자열 |
   | `GH_TOKEN` | 4단계에서 만든 토큰 |
   | `GH_REPO` | `joongyu01/news` |
   | `GH_BRANCH` | `main` |

   `SESSION_SECRET` 은 터미널에서 아래로 만드시면 됩니다.
   ```
   openssl rand -base64 32
   ```

5. **Deploy** 를 누릅니다. 끝나면 `https://....vercel.app` 주소가 나옵니다.
   이 주소가 담당자가 매일 열 **검토 페이지**입니다.

### 6. GitHub에 값 넣기

저장소 → **Settings → Secrets and variables → Actions**

**Secrets** 탭 (`New repository secret`):

| 이름 | 어디서 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | 1단계 |
| `TELEGRAM_CHAT_ID` | 1단계 |
| `NAVER_CLIENT_ID` | 2단계 *(선택)* |
| `NAVER_CLIENT_SECRET` | 2단계 *(선택)* |
| `GMAIL_USER` | 3단계 |
| `GMAIL_APP_PASSWORD` | 3단계 |
| `EMAIL_TO` | 받을 주소, 쉼표로 여러 개 |

**Variables** 탭:

| 이름 | 값 |
|---|---|
| `REVIEW_URL` | 5단계에서 나온 Vercel 주소 |

### 7. main 브랜치에 올리기

**GitHub 예약 작업은 기본 브랜치(main)에 있을 때만 돕니다.**
작업 브랜치에 그대로 두면 아침에 아무 일도 일어나지 않습니다.
Pull Request를 만들어 main에 합쳐 주세요.

## 잘 되는지 확인하기

설정을 마친 뒤, 다음 날 아침을 기다리지 말고 바로 시험해 보세요.

1. 저장소 **Actions** 탭 → **동향 수집** → *Run workflow* → `dry_run` 체크 → 실행
   로그에 기사가 쭉 나오면 수집이 정상입니다. 0건이면 아래 문제 해결을 보세요.
2. 같은 화면에서 `dry_run` 없이 한 번 더 실행합니다.
   텔레그램으로 "초안이 준비됐습니다" 알림과 검토 페이지 주소가 옵니다.
3. 검토 페이지를 열어 PIN을 넣고, 기사 몇 개를 눌러 제외해 봅니다.
   화면 아래에 **저장됨** 이 뜨고, 저장소 `data/exclusions/` 에 커밋이 생깁니다.
4. **동향 발송** → *Run workflow* → `dry_run` 체크 → 실행.
   제외한 기사가 빠진 최종본이 로그에 나오면 완성입니다.

## 매일 쓰는 법

검토 페이지의 **수집 기사 찾아보기**에서 저장된 기사 전체를 검색할 수 있습니다. **미발송**은 분야별 상한 초과·담당자 제외·중복 묶음 기사를 함께 보여주며, 각각의 필터로 나눠 볼 수도 있습니다. 중복 기사는 다른 매체의 제목과 원문 링크까지 표시합니다. 제목·매체·요약 검색, 분야 선택, 40건 단위 페이지 이동을 지원합니다. 이 열람 조건은 발송 내용에 영향을 주지 않습니다.

전체 건수는 대표 기사와 저장된 중복 기사 수를 합산합니다. 별도 기사 본문이나 수집 이력을 DB에 추가하지 않으며, 수집 단계에서 기간·분류·차단 조건으로 탈락해 초안에 저장되지 않은 기사는 이 목록에 포함되지 않습니다.

담당자가 할 일은 하나뿐입니다.

1. 아침에 텔레그램으로 오는 검토 알림의 링크를 엽니다.
2. 나가면 안 될 기사의 **✓ 버튼을 눌러 제외**합니다. 저장 버튼은 없습니다 — 누르면 바로 저장됩니다.
3. 그대로 두면 08:00에 최종본이 텔레그램·이메일로 옵니다.
   급하면 페이지 아래 **전체 복사** 를 눌러 바로 카카오톡에 붙여넣어도 됩니다.

검토를 못 하고 지나가도 08:00에 초안 그대로 발송됩니다. 빠뜨렸다고 그날 공지가
비는 일은 없습니다.

지난 날짜를 보려면 페이지 위쪽 날짜를 바꾸거나 `?date=2026-09-16` 을 주소에 붙이세요.

## 설정 바꾸기

[`config/news.yml`](config/news.yml) 한 파일만 고치면 됩니다. 코드는 건드릴 필요 없습니다.
고쳐서 main에 올리면 다음 날 아침부터 반영됩니다.

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 검색어 추가·삭제 | `sectors[].queries` |
| 섹터 분류 기준 조정 | `sectors[].must` / `sectors[].any` |
| 섹터별 기사 수 조절 | `limits` |
| ⚠️ 경보 키워드 | `risk_keywords` |
| 매번 빼는 기사 아예 안 뜨게 | `blocklist.title_contains` |
| 특정 매체 통째로 제외 | `blocklist.sources` |
| 몇 시간 이내 기사만 볼지 | `lookback_hours` |

섹터 순서가 곧 판정 순서입니다. 위에 있는 섹터가 먼저 가져갑니다.

## 문제 해결

**아침에 아무것도 안 왔습니다**
Actions 탭에서 실패한 작업의 로그를 보세요. 가장 흔한 원인은 `main` 브랜치에
올리지 않은 경우입니다(7단계). 그 다음이 Secret 오타입니다.

**시간이 밀립니다**
GitHub 예약 작업은 정시를 보장하지 않고 혼잡하면 5~20분 늦습니다. 정시가
중요하면 `.github/workflows/dispatch.yml` 의 cron을 30분 앞당기세요.
`0 23 * * *` 이 08:00 KST 입니다. UTC 기준이라 9시간을 빼서 적습니다.

**기사가 0건입니다**
네이버 키 없이 구글뉴스로 돌고 있을 수 있습니다. 로그 첫 줄의 `주 수집원` 을
확인하세요. 키가 있는데도 0건이면 `lookback_hours` 를 늘려 보세요.

**엉뚱한 섹터로 갑니다**
`config/news.yml` 의 `must` 에 단어를 넣으면 무조건 그 섹터로 갑니다.
`any` 보다 강하게 동작합니다.

**검토 페이지에서 저장이 안 됩니다**
`GH_TOKEN` 만료가 가장 흔합니다(4단계). Vercel 대시보드의 함수 로그에
실제 오류 메시지가 찍힙니다.

**같은 기사가 두 번 나옵니다**
제목이 많이 다르면 다른 사안으로 봅니다. `scripts/dedupe.py` 의
`SIMILARITY_THRESHOLD` 를 낮추면 더 공격적으로 묶습니다. 대신 서로 다른
사안을 잘못 묶을 위험이 함께 올라갑니다.

## 구조

```
config/news.yml            수집·분류 설정 (여기만 고치면 됩니다)
scripts/
  collect.py               06:40 — 수집해서 초안 생성
  dispatch.py              08:00 — 검토 반영해 발송
  weekly.py                금 08:30 — 주간 요약
  sources.py               네이버 API · 구글뉴스 · 업계지 RSS
  classify.py              섹터 판정, ⚠️ 키워드
  dedupe.py                같은 사안 묶기
  market.py                유가·환율
  render.py                평문 / 마크다운 / 이메일 HTML
api/                       검토 페이지 백엔드 (Vercel)
public/index.html          검토 페이지 화면
data/drafts/               날짜별 초안
data/exclusions/           날짜별 제외 목록
archive/                   발송된 동향 보관
tests/                     단위 테스트
```

발송본은 `scripts/render.py` 가, 검토 페이지의 미리보기는 `public/index.html`
이 각각 만듭니다. 둘이 어긋나면 담당자가 본 것과 다른 게 나가므로,
`tests/test_parity.py` 가 두 결과를 글자 단위로 대조합니다.

## 보안에 관해

- 검토 페이지는 **PIN 하나로만** 막혀 있습니다. 4자리는 마음먹고 시도하면
  뚫리는 길이입니다. 서버리스 구조라 시도 횟수를 세어둘 곳이 없어, 대신 실패할
  때마다 1초씩 늦추는 정도만 걸어 두었습니다. **Vercel 주소를 외부에 공유하지
  않는 것**이 실질적인 방어선입니다.
- 미발송 초안이 곧 대외비는 아니지만, 더 강하게 막아야 한다면 PIN을 6자리
  이상으로 늘리거나 Vercel의 접근 제한 기능을 검토하세요.
- 토큰·비밀번호는 **절대 저장소에 커밋하지 마세요.** GitHub Secrets 와 Vercel
  환경변수에만 넣습니다. `.env` 는 `.gitignore` 에 들어 있습니다.
