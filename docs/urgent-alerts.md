# 새 기사 선별·긴급 알림

수집과 AI를 분리합니다.

## 마스터 개인톡 관리

설정 변경과 운영 조회는 `owner`와 일치하는 소유자의 개인톡에서만 허용합니다. 단톡방은 뉴스 수신용이며 소유자의 그룹 명령도 거절합니다. 기존 구독방은 유지됩니다. `/subscribers`는 구독 개인톡·단톡방의 이름과 ID를 표시하며 그룹 참여자 명단을 조회하지 않습니다. `/subscribe_대화ID`, `/unsubscribe_대화ID`로 원격 구독 관리가 가능하고 ID를 생략하면 내 개인톡에 적용합니다. 새 대상은 봇과 대화를 시작했거나 봇이 참여한 방이어야 수신할 수 있습니다. 구독 목록 이름은 구독 등록 또는 매일 요약 실행 시 갱신됩니다.

매일 20:00 KST `daily-report.yml`이 소유자 개인톡으로만 운영 요약 한 건을 보냅니다. 일반 뉴스 구독을 해제해도 관리자 보고는 유지됩니다. `/daily_report`는 마지막 요약을 다시 보여줍니다. GitHub 예약 지연 시 실제 실행 시점까지 집계합니다. 실패 횟수는 당일 생성된 뉴스 워크플로 실행의 최종 상태 기준(재실행은 최종 결과)이며, 복구된 개별 API 오류 횟수가 아닙니다. API 조회 실패는 0회로 표시하지 않습니다. 수집 처리 합계는 반복 포함이고 새 집계 기능 적용 시점부터 기록합니다. 보관 중인 오늘 기사·AI 판정·긴급 발송 건수에는 기존 보관 한도가 적용됩니다. 조간 초안 존재는 발송 성공을 의미하지 않습니다.

같은 날짜 완료 보고 재실행은 건너뜁니다. Telegram 접수 후 응답 유실 또는 DB 저장 실패 시 재실행 중복 가능성은 남아 있습니다. 테스트 발송도 해당 날짜 보고로 기록됩니다. 권한 범위 확대나 새 외부 서비스 없이 기존 Actions·Supabase·Telegram 연결을 사용합니다.

## 예약

- `.github/workflows/alerts.yml`: 24시간 15분마다 수집·누적 저장만 실행합니다.
- `.github/workflows/screening.yml`: 06:00~23:30 KST 매시 00/30분, 저장된 새 기사 최대 40개를 Gemini 3.8 Flash로 선별합니다. 실패 시 3.7 Flash, 3.1 Flash-Lite 순서로 시도합니다.
- `.github/workflows/collect.yml`: 05:17 KST 예약(08시 전 수신 목표), 최근 24시간 선별 자료를 종합 분석한 뒤 조간을 발송합니다.

예약은 지연될 수 있습니다. AI 선별은 실행 시점이 00:00~05:59면 생략합니다. 별도 수집은 밤에도 계속됩니다.

## 긴급 기준

AI가 새 사건이나 중요한 새 변화로 판정하고, 사고·공급 중단·확정 긴급 정책 등 기존 규칙도 통과해야 합니다. 기사 게시 시각과 사건 발생 시각을 구분합니다. 과거 사건 재서술, 해설, 원인 추정, 일반 기관 통합 보도는 긴급 제외입니다. 해외 원문은 조간 전용입니다.

같은 사건 키와 URL·유사 제목 이력을 함께 비교합니다. 수신방당 최대 3건을 제목 하이퍼링크가 있는 한 메시지로 보냅니다. 후보가 없으면 보내지 않습니다. 방별 일일 상한과 휴식 설정도 계속 적용합니다.

## API와 실패 처리

Groq 사용 시 Actions `AI_PROVIDER=groq`와 무료 확인 변수/Secret을 설정한다. 모델은 Qwen 3.8 27B이고 reasoning을 끈다. 실제 계정 Free($0), 모델 한도 30 RPM·1,000 RPD·8,000 TPM·200,000 TPD를 2026-09-25 화면에서 확인했다. 18만 토큰 고정 제한은 없다. 최근 24시간 사용 추정치 기준 무료 20만 토큰에서 조간 1회분 최대 7,800토큰을 남긴다. 일반 요청은 하루 최대 39회, 조간은 40번째 요청까지 허용한다. 자정에도 최근 사용량은 유지하며 서버의 실제 한도 초기화와 다를 수 있다. 성공 시 실제 사용량으로 정산하고 실패 시 예약량을 유지한다. 계정이 무료로 유지되는 것이 무과금 조건이며 변수 자체는 결제 상태 조회가 아니다. 입력 제목·요약 및 이전 문맥을 줄여 요청 상한에 맞춘다. 입력은 UTF-8 바이트 기준 여유 포함 6,000, 출력 최대 1,800토큰이다. 개별 요청 실패와 한도 초과 때 자동 유료 대체/재시도를 하지 않는다. 긴급은 실패 알림, 조간은 기존 기본 스크랩으로 대체한다. [Groq 공식 한도](https://console.groq.com/docs/rate-limits).

아래 Gemini 동작은 AI_PROVIDER가 groq가 아닐 때에만 적용한다.

A/B 프로젝트 키를 요청마다 교대로 사용합니다. 모델별 1회, 재시도 포함 하루 40회 상한을 둡니다. 선별·조간의 순번과 횟수는 공유합니다. 두 프로젝트는 결제 미연결 무료 등급을 유지해야 합니다.

긴급 선별 AI 실패 시 신규 결과를 발송하지 않고 소유자에게 오류 알림과 Actions 로그 링크를 보냅니다. 같은 단계 오류는 6시간에 한 번으로 제한합니다. 조간은 AI 실패 안내를 포함한 기본 스크랩을 발송합니다. DB 장애로 중복 기록을 읽을 수 없으면 오류 알림을 우선합니다.

검증: `--collect-only --dry-run`은 수집만, `--screen-only --dry-run`은 저장된 판정만 확인합니다. `--screen-only --no-send`는 실제 API를 호출하고 판정·사용량을 저장하되 뉴스 발송은 생략합니다.

## 2026-09-25 조간 예약 보정

08:00 예약의 최근 실행 시작은 9/22 10:24, 9/23 10:11, 9/24 10:00, 9/25 10:06으로, 지연은 평균 약 130분·최대 144분이었다. 이에 UTC 전날 20:17 = KST 05:17로 예약을 앞당겼다. 동일 지연이면 07:17~07:41 시작이 예상되며 최대 15분 작업 제한도 감안했다. 지연이 줄면 더 일찍 발송될 수 있고 08시 전 도착을 보장하지 않는다. 이전보다 기사 마감 시각이 앞당겨지며 이후 기사는 정기 수집·긴급 선별에서 처리한다.

GitHub 계정 Notifications → Actions는 웹·이메일을 유지하고 Failed workflows only로 저장했다. 이는 저장소 전용이 아닌 계정 Actions 알림 설정이며 뉴스 이메일 발송과 별개다.

9/25 긴급 선별 #22(13:28 예약 실행)는 3.8·3.7 HTTP 503 이후 3.1 Flash-Lite 분석에 성공했고, 긴급 후보·발송은 0건이었다. 수집 갱신은 당시 154분 지연됐으며, 예약 간격과 실제 실행 간격이 다르므로 30분마다 정상 감시된다고 단정하지 않는다.
