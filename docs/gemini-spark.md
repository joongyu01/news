# Gemini Spark 뉴스 검토와 Telegram 전달

Gemini 웹의 기존 유료 구독으로 Spark 예약을 실행합니다. Gemini API 키나 별도 모델 API 과금은 사용하지 않습니다. 사용자 PC를 켜둘 필요가 없으며 Google 서버의 예약이 작동합니다. 현재 설정은 매시간 정각, 공개 석유·가스 뉴스를 검토하고 새 중요 소식만 보고하는 방식입니다. 실행 시간과 가용성은 구독 한도와 Google 서비스에 따릅니다.

**완전 무인 전달은 보장되지 않습니다.** Google은 원격 브라우저 사용과 웹 양식 제출 시 사용자 확인을 요구할 수 있습니다. 2026-09-19 실제 점검에서 브라우저 사용과 제출을 각각 승인한 뒤 Gemini의 접수, GitHub 전달, Telegram 수신이 성공했습니다(18:11 KST, [Actions 실행](https://github.com/joongyu01/news/actions/runs/35434024336)). 이후 예약의 `지금 실행` 시험은 원격 브라우저 시간 초과로 실패했고, 재시도는 브라우저 승인을 다시 요구했습니다. 따라서 이 연결을 승인 없이 항상 동작하는 긴급 전달 수단으로 간주하면 안 됩니다. 기존 규칙 기반 뉴스 알림은 Gemini와 별도로 동작합니다. [Google의 확인 절차 안내](https://support.google.com/gemini/answer/17094507?hl=en).

예약에는 승인 필요·오류로 미전달된 경우 Gemini에서 실제 상태를 알리고, 일시적 오류는 한 번만 재시도하도록 지시했습니다. 테스트용 지시는 제거하고 정규 뉴스 검토 지시를 복원했습니다.

검토 결과는 Gemini 원격 브라우저에서 `https://news-lake-delta.vercel.app/spark.html`에 제출합니다. 제출 전용 키는 로그인된 담당자가 페이지의 관리자 연결 설정에서 불러옵니다. 이 키는 보고서 제출과 접수/발송 상태 확인에만 쓸 수 있고 초안, 제외 목록, 봇 설정에는 접근할 수 없습니다. Telegram 토큰, Supabase 키, 담당자 PIN을 Gemini에 제공할 필요가 없습니다. 링크로 전달할 때 키는 `#key=...` fragment에 넣고 서버 요청 로그에 포함하지 않습니다. 키를 공유할 대상은 승인된 Gemini Spark 계정입니다.

Spark 지침에는 공개 뉴스 요약을 최대 3000자로 제출하고, 새 중요 소식이 없으면 제출하지 않도록 지정합니다. 접수는 즉시지만 실제 발송은 기존 `긴급 뉴스 알림` Actions의 다음 실행에서 처리합니다(15분 예약, 지연 가능). 소유자 개인 대화로만 발송하며 그룹에는 전달하지 않습니다. 소유자의 `/urgent off`, `/quiet`, `/limit`를 적용합니다. 제한이 있으면 Gemini와 기존 규칙 알림의 합산 수를 사용합니다.

저장은 기존 `news_bot_settings` 한 행을 재사용합니다. 전달 대기는 최대 3건·보고당 3000자, 24시간이 지난 대기는 제거합니다. 발송 성공 후 본문을 제거하고 중복 방지용 해시와 발송 시각만 7일·최대 100건 보관합니다. 기존 테이블의 총 64KB 제한을 유지하고 입력 시 60KB에서 차단합니다. 평문 기사 전문을 쌓지 않습니다. 전체 DB 물리적 사용량에는 인덱스·테이블 등의 오버헤드가 포함됩니다.

설정 수정과 전달 완료 처리는 revision 비교로 충돌을 재시도합니다. Telegram 수신 직후 DB 기록 전에 프로세스가 중단되면 재발송될 수 있습니다. Gemini가 표현을 바꾼 같은 사건은 다른 해시가 되므로 의미 중복 검토는 Spark 작업 지침에서 수행합니다.

연결 취소 시 Gemini 예약에서 제출 링크를 지우고 작업을 일시중지하세요. 전용 키를 폐기하려면 Vercel `SESSION_SECRET`을 교체합니다. 기존 검토 페이지 세션도 만료되므로 운영자가 재로그인해야 합니다.
