# 다른 세션에서 Edge Computer Use로 이어가기

기록 기준: 2026-09-19. 아래는 마지막 확인 상태이며 새 세션에서 실제 상태를 다시 확인한다. 계정 인증정보와 비밀값은 이 문서에 없다.

## 시작 순서

1. 저장소의 `AGENTS.md`와 현재 요청을 읽고 필요한 작업 범위를 정한다.
2. 현재 세션의 스킬 목록에서 `computer-use:computer-use`의 `SKILL.md`를 읽는다. 버전이 들어간 과거 설치 경로를 고정하지 않는다.
3. 현재 브라우저 도구의 초기화 지침을 따른다. 이 프로젝트에서 사용한 도구는 `mcp__cua_repl.js`이며 Edge 확장 연결로 동작했다. 이 도구가 있으면 도구 문서의 `cua` API를 사용한다. 과거 스킬의 `sky` 예제가 현재 도구 설명과 다르면 현재 제공된 도구 지침을 우선한다.
4. 사용자가 지정한 Edge에서 현재 탭과 로그인 계정을 확인한다. 탭 ID, 브라우저 ID, REPL 변수, 화면 요소 번호는 세션 간에 유지된다고 가정하지 않는다.
5. 해당 페이지를 읽고 필요한 설정을 바꾼 뒤 성공/실패 표시와 실제 결과를 확인한다. 문서에 적힌 과거 성공을 이번 작업의 검증으로 대신하지 않는다.

`mcp__cua_repl.js`의 현재 문서가 동일한 API를 제공할 때, 새 세션에서 열린 브라우저/탭 목록이 필요하면 첫 호출은 다음 한 줄만 실행한다.

```javascript
await cua.getState();
```

사용자가 탭을 직접 지정했다면 도구 문서에 따라 그 탭을 먼저 선택한다. 조회 결과로 Edge와 대상 탭을 선택한 다음 화면 상태를 읽는다. 클릭·입력 후에는 최신 접근성 트리나 DOM을 다시 확인하고 그 결과에 있는 요소를 사용한다. 지원되는 API만 쓰고, 셸이나 별도 자동화 라이브러리로 브라우저 세션·쿠키를 우회해서 다루지 않는다.

브라우저 연결이 끊겼으면 해당 브라우저의 연결/문제 해결 안내를 확인한다. 확장 연결이나 로그인이 실제로 필요한 경우에만 사용자에게 그 부분을 요청한다. 이 MD 파일은 확장을 설치하거나 로그인·권한을 자동으로 부여하지 않는다.

## 현재 수집·발송 구조

- 아침: GitHub Actions가 매일 06:40 KST에 수집하고 08:00에 동향을 발송한다. 주간 요약은 금요일 08:30. 예약 지연이 있다.
- 수집은 구글뉴스 검색 RSS와 업계지 5곳 RSS 중심이다. 네이버 키가 설정되면 뉴스 검색 API를 사용한다. 마지막 확인 당시 네이버 API 키는 미설정이었다.
- 수집 내용은 제목·매체·시각·링크·제공되는 짧은 요약이다. 개별 기사 본문 전체를 읽는 브라우저 크롤링은 구현되어 있지 않다.
- 긴급 점검은 매시 7/22/37/52분 예약이며 제목 규칙으로 선별한다. 유료 AI API를 쓰지 않는다. 기본 알림 강도는 `standard`, 일일 제한 없음이며 사용자가 봇 명령으로 변경할 수 있다.
- 에너지시장감시단과 석유공사·가스공사 통합 소식은 아침 스크랩·긴급 점검·Gemini 예약에 모두 포함되어 있다.
- 초안과 제외 목록은 Supabase를 사용한다. 저장 구조와 기존 GitHub 파일 경로는 [Supabase 안내](../supabase/README.md)를 참고한다.
- 관리자 페이지는 저장된 대표 기사뿐 아니라 중복 묶음도 표시한다. 전체/발송 예정/미발송/상한 초과/담당자 제외/중복 필터, 검색과 40건 단위 페이지 이동이 있다. 수집 단계에서 버려져 저장되지 않은 원시 기사까지 복원하는 기능은 아니다.

## 사용량·로그 확인

소유자 개인 대화의 아래 명령을 사용한다. 그룹에는 운영 수치를 공개하지 않는다. 이 명령을 실제 전송하는 것은 현재 요청에 포함되거나 사용자 승인을 받은 경우에 한다.

| 명령 | 결과 |
| --- | --- |
| `/usage` 또는 `usage` | 최근 GitHub API 호출 잔여량·초기화 시각·캐시 용량·실행 시간 과금 구분 |
| `/logs` 또는 `logs` | 최근 저장된 초안과 긴급 점검의 시각·건수, 워크플로 상태 |
| `/logs 수집` 또는 `/logs collect` | 아침 수집 최근 3회, 상세 로그 링크 |
| `/logs 긴급` 또는 `/logs alerts` | 긴급 점검 최근 3회, 상세 로그 링크 |
| `/logs 발송` 또는 `/logs dispatch` | 발송 최근 3회, 상세 로그 링크 |
| `/status`, `/help` | 현재 방 설정, 명령 사용법 |

`/usage`는 모델 토큰 잔액이나 계정 전체 결제 잔액이 아니다. 15분 예약 작업이 갱신한 스냅샷이며 조회 시각과 오래된 값 경고를 표시한다. 공개 저장소의 표준 runner 실행 시간은 무료라는 조건부 안내를 한다. 정확한 청구는 GitHub Billing에서 확인한다.

`/logs`는 DB의 최신 초안·긴급 요약과 캐시된 GitHub 실행 기록을 함께 보여준다. 수동 실행에는 `dry_run`도 있으므로 워크플로 성공을 실제 메시지 발송으로 단정하지 않는다. 원시 수집→신선도→분류 단계별 숫자는 해당 기능 추가 후 생성된 초안부터 제공한다.

2026-09-19에 `cea8506` 배포, CI, `봇 명령 연결` 실행과 Telegram `/usage`, `/logs` 응답을 확인했다. 이후 변경은 현재 커밋과 실행 화면을 기준으로 판단한다.

## Gemini 연결에서 구분할 상태

Gemini는 웹 유료 구독의 Spark 예약을 사용하며 별도 Gemini API를 쓰지 않는다. 기존 예약은 매시간 정각이다. Google 서버 예약과 GitHub 작업은 PC가 꺼져도 실행되지만, Gemini의 원격 브라우저·양식 제출 승인이 필요하면 전달이 멈출 수 있다.

보고 접수와 Telegram 발송 완료는 별개다. Google 승인 → 접수 상태 → 다음 Actions 실행 → 실제 Telegram 수신을 각각 확인한다. 완전 무인 전달이 된다고 보고하지 않는다. 구체적 제약과 저장 한도는 [Gemini 연결 안내](gemini-spark.md)에 있다.

연결 키는 관리자 페이지의 지원되는 UI에서 다룬다. 보고 제출 전용 키를 Telegram 토큰이나 Supabase 서비스 키와 혼동하지 않는다. 비밀값, 키가 포함된 링크/화면, PIN을 문서·Git·로그에 남기지 않는다. 새 대상에게 키를 전달하는 권한을 이 문서로 추정하지 않는다.

## 코드 변경과 검증

- 수집 경로: `scripts/sources.py`, `scripts/collect.py`, `config/news.yml`
- 긴급 점검: `scripts/alerts.py`, `config/alerts.yml`
- 명령/webhook: `api/_bot.js`, `api/telegram.js`, `scripts/bot_setup.py`
- 사용량/로그: `scripts/github_usage.py`, `api/_usage.js`, `api/_logs.js`
- 관리자 화면: `public/index.html`
- Gemini 전달: `public/spark.html`, `api/spark.js`, `scripts/spark_relay.py`

코드·테스트·Git은 로컬 셸로, 웹 설정과 운영 화면 확인은 지원되는 Edge Computer Use로 처리한다. 변경에 맞는 테스트를 실행하고, 배포한 경우 해당 커밋의 CI/Vercel 결과와 실제 동작을 확인한다. 명령 메뉴를 수정했다면 배포 후 Actions의 `봇 명령 연결`을 한 번 실행한다. 이 작업은 메뉴와 webhook을 갱신하고 사용량을 초기 조회하므로 이미 정상인 상태에서 불필요하게 반복하지 않는다.

DB는 크기를 제한한다. 긴급 발송 이력은 7일/최대 500건, 봇 설정은 단일 행/64KB, GitHub 실행 요약은 3종류×최근 3개이다. Gemini 큐·이력의 별도 한도도 유지한다. 저장된 모든 초안에 같은 보관 정책이 적용된다고 가정하지 않는다.

## 지침을 다음 세션에 전달하는 방법

저장소 루트의 `AGENTS.md`가 이 문서를 안내한다. 같은 PC의 공통 `~/.codex/AGENTS.md`에도 Edge 선호와 이 저장소 위치를 기록했다. 다른 PC에서 작업하면 저장소를 열고 이 문서를 읽히며, Computer Use 도구·확장 연결·로그인은 별도로 준비되어 있어야 한다. 이미 열린 세션에는 “AGENTS.md와 docs/computer-use-handoff.md를 읽고 이어서 작업해줘”라고 알려주면 된다.
